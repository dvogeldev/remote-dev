# Hermes v0 Nostr identity lives in `~/.hermes/.env` (with mirror files)

Source of truth for the single v0 Nostr keypair is `BUZZ_PRIVATE_KEY` in `~/.hermes/.env` (chmod 0600, the pass→env checkout per ADR #0007). The bundled `plugins/platforms/buzz/` adapter reads it directly. As a human-shareable mirror, `~/.hermes/nostr.npub` (chmod 0644) and `~/.hermes/nostr.nsec` (chmod 0400) are written by the provision step, derived from the same nsec. They exist for two human uses only: paste the npub into Buzz admin onboarding / docs, and a defense-in-depth backup under the pass tree. No new `hermes identity` CLI surface in v0 — the operator handles the .env exactly like other secrets via `pass`. Per-profile identity (a separate ticket, deferred past v0) will migrate the mirror files to `~/.hermes/<role>/nostr.{npub,nsec}` and split `.env` per profile. Did not pick env-only (no on-disk files): no human-shareable npub without deriving it each time. Did not pick a combined `nostr.identity` config file: finer-grained permissions on the nsec matter. Did not pick `~/.hermes/default/`-prefixed paths from day one: speculative when v0 has one profile and burns a rename when per-profile lands.
