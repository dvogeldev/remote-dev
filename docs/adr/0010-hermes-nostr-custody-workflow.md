# Hermes v0 Nostr keypair generation & custody (single-key)

Source of truth is the operator laptop. Generation runs with `nak key generate` (NIP-19 bech32 `nsec1...`), the nsec lands in a single-line `pass` entry at `nostr/hermes-buzz/private-key`, and the existing pass → `~/.hermes/.env` SSH flow (per ADR #0007 and `scripts/unwrap-hermes-env.sh`) renders it as `BUZZ_PRIVATE_KEY` on the VPS. Mirror files at `~/.hermes/nostr.npub` (0644) and `~/.hermes/nostr.nsec` (0400) are produced by a **chezmoi run_onchange hook** that derives the npub from the same `BUZZ_PRIVATE_KEY` value (via `nak key public`, the inverse of the chosen generator), so the npub can never drift from the nsec. Generated on the laptop, stored only on the laptop in `pass`, surfaced on the VPS by chezmoi+pass — the secret never touches an unencrypted medium. Per-profile identities (deferred past v0) get a new pass entry per role and a per-profile chezmoi template; the unwrap script grows to handle profile scoping when that lands. Did not pick VPS-side keygen: would invert the existing trust model (ADR #0007 keeps secrets originated on the laptop). Did not pick multi-line `nostr/hermes-buzz/identity` (nsec + npub): one encrypted blob to rotate, not two. Did not pick adapter-managed mirror files: the bundled `plugins/platforms/buzz/` adapter does not write nostr.npub/nostr.nsec — identity is constructed in-memory from `BUZZ_PRIVATE_KEY` and `buzz users get`, then discarded.
